# VOID — 音と触覚だけで空間を歩くリラックス系プロトタイプ (iOS / SwiftUI)

真っ黒な画面。**両手の親指が、あなたの両足**。
交互に下へ払うと一歩ずつ進み、一歩ごとに足音と振動が返る。
遠くで鳴り続ける音を頼りに、見えない空間を歩いていく。

失敗もゲームオーバーもない。歩くという行為そのものが体験。
**できれば目を閉じて**、**ヘッドホンを着けて**プレイしてほしい。

---

## 入力の設計

両手の親指を「足」として扱う。指1本のポインタではなく、**身体そのもの**として動かす。

| 動作 | 意味 | 挙動 |
|---|---|---|
| 左右の親指を**交互に下へ払う** | 歩く | 下方向の動きだけが推進力になる。上へ戻す動きは足を前に運び直す動作にあたり、空振りする |
| 同じ親指を続けて払う | — | ゲインが `sameFootGain`（既定 0.22）まで落ちる。左右交互でないと前へ進まない |
| **片方の親指を止める** | 舵に持ち替える | 0.4秒静止すると回頭モードに入り、カチッと鳴る（`RotateStart.wav`）。この間は前進しない |
| 回頭モード中に親指を動かす | 回る | 両親指を結ぶ線＝肩のライン。線が回った角度がそのまま進行方向に乗る（既定 1:1）。9時→10時の30度で30度回る |
| 親指を離す | 歩行に戻る | 持続音が消える。置き直せばまた歩ける |

回頭モードに入ってしまえば、**どちらの親指を動かしても**舵になる。
「片方を止めてもう片方を動かす」でも「片方を下・片方を上」でも同じように回る。
抜けるのは指を離したときだけで、速度で抜けるようにはしていない。
そうすると「片方を下・片方を上」で回している最中にモードが切れて、効いたり効かなかったりする。

前進は指の動きと **1:1 で即時**に反映する（平滑化すると足の裏の感じが鈍る）。

### 歩行と回頭は、信号としては区別できない

交互に払う動作は、それ自体が**肩のラインの回転そのもの**である。
左が下がって右が上がる形は、幾何学的には「回した」のと同一で、区別する情報が入力に存在しない。
だから信号側で切り分けようとする試みは、ことごとく破綻する。

実際に試して駄目だったもの:

- **「片方が止まっている＝回頭」**: 歩行にも片方が止まる瞬間があるので誤発火し、
  まっすぐ歩いているつもりで曲がる
- **「下方向のストロークのときは回頭しない」**: 足を戻す上方向のストロークぶんが
  打ち消されずに残り、やはり一歩ごとに曲がる
- **「踏み込みが止まって一定時間経ったら回頭できる」**: 肩のラインを回すと
  必ずどちらかの親指が下がるので、その向きの回転が毎回ブロックされる

結論として、**ホールドという明示的な操作でモードを分ける**のがいちばん確実だった。
片方を 0.4秒 止めれば舵に持ち替わり、その合図が Zippo の音で返る。
モードの間は前進しないので、舵を切るために親指を下げても歩き出さない。
歩行中は肩のラインが傾いても向きは一切変わらないので、ただ歩けばまっすぐ進む。

### 隠しジェスチャは指2本を避ける

タイトルへ戻る操作は当初 2本指ダブルタップだったが、両手の親指で歩く操作と衝突する。
親指を置き直すたびに2本指タップが成立してしまい、
回頭のために持ち替えるだけでタイトルへ戻されていた。
遊んでいる間に絶対に起きない本数（4本指）まで離す必要がある。

> 不感帯は**角速度**（度/秒）で持つこと。フレームあたりの角度で書くと、
> 120Hz では 0.12°/フレーム = 14°/秒 という巨大なしきい値になり、
> ゆっくり慎重に回したときに丸ごと捨ててしまう。

### 蛇行（まっすぐ歩けないこと）

目を閉じて歩くと、人間は実際にまっすぐ歩けない。少しずつ逸れて、やがて円を描く。
これを難易度調整ではなく**モデルとしてそのまま**入れてある。

一歩ごとに、持続性のあるランダムウォーク（AR(1)、既定の持続性 0.88）で進行方向が逸れる。
毎歩バラバラに揺らすと単なるノイズになって方向感が消えるので、
**しばらく同じ方向へ曲がり続ける**性質を持たせている。

結果として「音のほうを向いて、あとは真っ直ぐ」が成立しなくなり、
数歩ごとに聴き直して直す必要が生まれる。歩き続けている間ずっと耳を澄ませている状態になる。

## 音の設計

| 音 | 定位 | 役割 |
|---|---|---|
| **足音** | させない（左右のパンのみ） | 自分の足元で鳴るもの。実録音のサンプル（`Resources/Footstep_L.wav` / `_R.wav`）を左右で使い分ける |
| **beacon** | バイノーラル（HRTF） | 脈打ち続ける方角の基準。洞窟の部屋の中に置かれる |
| **回頭のフィードバック** | バイノーラル（HRTF） | 回頭モードの間だけ鳴る。モードに入った瞬間の**前方**にワールド固定で置くので、体が回るぶんだけ音が横へ流れていく |

### 回転を「音が自分の周りを回る」形で伝える

回頭モードに入った瞬間の正面 6m に音源を置き、そこでカチッと鳴らして（`RotateStart.wav`）から
持続音（`RotateBed.wav`）を立ち上げる。音源はワールド座標に固定したままなので、
自分が回るぶんだけ音が横へ流れる。**回転そのものを聴いている**状態になる。

カチッはモードに入った合図も兼ねていて、目を閉じていても舵に切り替わったことが分かる。
モードを抜けると持続音は消える。次に入れば、また新しい正面に置き直される。

`AVAudioEnvironmentNode` の HRTF レンダリングで空間化している。
自分が30度回れば音源は逆に30度回るので、**耳だけで自分の向きが読める**。

### 定位できる音の条件

音源が1つだけだと「動いた」しか分からないので、方角の基準は**3つ**置いている。
複数あって初めて、星座が回るように何度回ったのかが読める。

さらに、**どんな音を鳴らすかで定位のしやすさが決定的に変わる**。

- **アタックがあること。** 持続音だけだと両耳への到達時間差が読めず、方向が立たない。
  基準音は脈打たせてある（音源ごとに周期を変えて聴き分けられるようにしている）。
- **倍音が 1〜3kHz に届くこと。** 低い純音は人間が最も定位できない信号で、
  ILD がほぼ生まれず前後の取り違えも起きる。基音は 233〜392Hz に置き、
  倍音を 8 倍音まで伸ばして、手がかりの効く帯域にエネルギーを乗せている。
- **わずかな残響。** 頭の中ではなく「外」で鳴っている感じ（頭外定位）が出て、
  方向が格段に読みやすくなる。入れすぎると定位が滲む。

## 空間（洞窟）

広い部屋と狭い通路がつながった洞窟状の空間を、セッションごとにランダムに生成する。
部屋を数珠つなぎにした構造で、進む方向は前回から±70度以内に収まるので、
折り返しの多い団子状ではなく伸びていく洞窟になる。基準音は出発点以外の部屋へ散らして置かれる。

**いまいる場所の広さが、そのまま残響になる。**

- 響きの**量**（レベルと混ぜ具合）は連続的に動く
- 響きの**長さ**（プリセット）は段階的に切り替わる。狭い通路 → 小部屋 → 広間 → 洞窟。
  レベルだけを動かしても「量」が変わるだけで「空間の大きさ」までは変わらないため。
  行ったり来たりしないようヒステリシスを入れてある

狭い通路を抜けて広間に出た瞬間に響きが開く、という体験を作るためのもの。
広さの変化は `spaceSmoothing`（既定 0.7秒）で均してあり、部屋の境目で残響が飛ばない。

> 壁としての**当たり判定は持っていない**。洞窟は「その地点がどれくらい広いか」を
> 返すだけの層で、岩の中へ歩いていくこともできる（そのときは響きが締まる）。

> **HRTF には正面と真後ろを取り違えるという人間側の限界がある。**
> これを解消する唯一の方法が首や体を振ることなので、
> 回頭は移動手段であると同時に「曖昧さを解く行為」でもある。

## 触覚の設計

一歩ごとの短いトランジェント。左右でわずかに質感を変えてあり、
どちらの足で踏んだかが触覚だけでも分かる。

連続触覚のしくみ（無限ループパターン＋Dynamic Parameters）は
`HapticsController` にそのまま温存してある。距離に連動する持続音を重ねる余地を残すため。

## 操作

| 操作 | 動作 |
|---|---|
| 両親指を交互に下へ払う | 歩く |
| 両親指を結ぶ線を傾ける | 曲がる |
| 3本指タップ | デバッグ表示のトグル |
| 4本指タップ | タイトルへ戻る |
| タイトルの「VOID」を長押し（1.2秒） | デバッグ表示のトグル（隠しスイッチ） |
| タイトルの「触覚テスト」 | 実機で触覚が動くかの確認（弱くざらつく → 強くなめらか → パルス） |

デバッグ表示では、歩数・現在地・進行方向・速度・蛇行量・足ごとの踏み込み量・
最寄りの基準音の方位と距離がリアルタイムで見える。

下部には**上から見た小さな地図**があり、洞窟（部屋と通路）が淡い塗り、歩いた軌跡が線、
現在地が点、向きが点から伸びる線、基準音が丸で描かれる。上が北。
触覚と音だけでは「本当に回れていたのか」が確かめられないので、
感覚と実際の挙動を突き合わせるために用意している。

## 動かし方

```
open haptic-void/HapticVoid.xcodeproj
```

1. TARGETS → HapticVoid → Signing & Capabilities で自分の Team を選ぶ
   （`PRODUCT_BUNDLE_IDENTIFIER` は必要に応じて変更）
2. **実機（iPhone）** を選んで Run
3. **ヘッドホンを着ける**（スピーカーだと空間定位は完全に失われる）

> `.xcodeproj` は `project.yml` から XcodeGen で生成している。
> ファイルを追加・削除したら `cd haptic-void && xcodegen generate` で作り直す。
> 署名設定（`DEVELOPMENT_TEAM` / `PRODUCT_BUNDLE_IDENTIFIER`）も `project.yml` 側に
> 入れてあるので、再生成しても崩れない。

- iOS 17.0+ / Swift 5 / 依存ライブラリなし
- ポートレート固定・フルスクリーン

## シミュレータでの挙動（重要）

**Core Haptics はシミュレータでは動作しない。** 実機テストが前提。

- `CHHapticEngine.capabilitiesForHardware().supportsHaptics` を起動時に確認し、
  false ならハプティクス層は**すべて no-op になる**（クラッシュも例外も出ない）
- 音とデバッグ表示はシミュレータでも動くので、**歩行ロジックの検証はできる**
  （歩数・現在地・進行方向・landmark の方位が数値で追える）
- タイトル画面に「⚠︎ この端末では触覚が再生されません（音のみで動作します）」と表示される

つまり **シミュレータ = 「数値でロジックを見る」用、実機 = 「歩き心地を詰める」用**。

なお実機でも、以下の場合は振動しない:
- 低電力モードがオン
- アプリがフォアグラウンドにない（**画面オフ中は触覚も音も止まる。iOSの制約**）
- iPhone 7 以前 / iPad（Taptic Engine 非搭載）

コンセプトの「画面オフでも成立する」は iOS では実現できないため、代わりに
真っ黒な画面＋`isIdleTimerDisabled = true`（自動ロックを止める）で、
目を閉じたまま中断されない状態を作っている。

## パラメータ調整

数値はすべて `HapticVoid/Core/Tuning.swift` に集約してある。ロジックには一切ハードコードしていない。

```swift
Tuning.Walk.strideStrokeRatio        = 0.11  // 一歩ぶんの親指ストローク（画面高さ比）
Tuning.Walk.strideAdvance            = 0.7   // 一歩で進む距離（メートル）
Tuning.Walk.sameFootGain             = 0.22  // 同じ足を続けたときのゲイン。1.0 で歩行感が消える
Tuning.Walk.steeringGain             = 1.0   // 肩のライン → 進行方向。1.0 で 1:1
Tuning.Walk.invertSteering           = false // 曲がる向きが逆に感じたらここ
Tuning.Walk.pivotHoldTime            = 0.4   // 親指を止めてから舵に持ち替わるまで（秒）
Tuning.Walk.pivotStillSpeed          = 60    // 静止とみなす親指の速度（ポイント/秒）
Tuning.Walk.blindDriftDegreesPerStep = 2.2   // 蛇行の大きさ。0 で完全にまっすぐ歩ける
Tuning.Walk.blindDriftPersistence    = 0.88  // 大きいほど同じ方向へ逸れ続ける
Tuning.Footstep.level                = 0.9   // 足音サンプルの音量
Tuning.Rotation.distance             = 6.0   // 回頭フィードバック音を置く距離（メートル）
Tuning.Cave.chamberRadiusRange               // 部屋の広さの範囲。残響の振れ幅を決める
Tuning.Audio.Space.reverbPresetSwitching     // 残響の長さも切り替えるか
Tuning.Audio.enabled                 = true  // 触覚だけの体験を試すときは false
```

### おすすめの詰め方

1. まず `blindDriftDegreesPerStep = 0` にして、**歩幅と足音のリズム**だけを詰める
   （`strideStrokeRatio` と `strideAdvance`）
2. `steeringGain` で曲がりやすさを取る。交互に払うと肩のラインが左右に振れるので、
   歩いているだけでも自然に揺らぐ。この揺らぎが強すぎるならここを下げる
3. `sameFootGain` で「片手だけでは進めない」の強さを決める
4. 最後に蛇行を戻し、数歩ごとに聴き直す頻度がちょうどよくなる量を探す

### 実装メモ

- **`DragGesture` は指を1本しか区別できない**ので、両手の親指を別々の足として扱うには
  UIKit のマルチタッチ層（`DualThumbTracker`）が要る。`UITouch` のインスタンスを
  そのまま識別子に使い、どちらの指が動いたのかをフレームをまたいで追跡している。
- 回頭は肩のラインの**角度の差分**を積むので、指を置き直しても回頭しない。
  1フレームで飛びすぎた変化（既定 25度超）は持ち替えとみなして捨てている。
- 連続触覚は**1本の無限ループパターンを鳴らしっぱなし**にして、Dynamic Parameters
  （`hapticIntensityControl` / `hapticSharpnessControl`）だけを書き換える設計を温存。
  毎回パターンを作り直すと途切れてグラデーションにならないため。
- `hapticSharpnessControl` は絶対値ではなく**イベント鋭さへの加算オフセット**（-1...1）。
  パターン側の基準値を 0.5 に置き、`目標値 - 0.5` を送ることで絶対値指定に見せている。
- 指が静止するとタッチイベントが止まるので、更新は CADisplayLink の固定ティックで回している。
- 空間音源は**モノラルで繋がないと定位が効かない**。`AVAudioEnvironmentNode` への接続は
  モノラル、出力はステレオ。基準音は脈の減衰が周期の終わりでゼロに落ちるので、
  ループの継ぎ目は自然に消える。
- 足音は `AVAudioPlayerNode` を4本プールして使い回している。1本を止めて鳴らし直すと
  一歩ぶん遅れて聴こえるので、全部を再生状態のままにして `scheduleBuffer` だけを投げる。

## いまの段階

第1段階として**歩き心地だけ**を確かめるための版。
音源は方角の基準になる beacon が3つあるだけで、探索対象と到達判定はまだ入れていない。
洞窟にも当たり判定は無く、いまは残響を動かすためだけに存在している。
