# VOID — 音と触覚だけで空間を歩くリラックス系プロトタイプ (iOS / SwiftUI)

真っ黒な画面。**両手の親指が、あなたの両足**。
交互に下へ払うと一歩ずつ進み、一歩ごとに足音と振動が返る。
遠くで鳴り続ける音を頼りに、見えない空間を歩いていく。

失敗もゲームオーバーもない。歩くという行為そのものが体験。
**できれば目を閉じて**、**ヘッドホンを着けて**プレイしてほしい。

---

## 入力の設計

両手の親指を「足」として扱う。指1本のポインタではなく、**身体そのもの**として動かす。

| 動作 | 意味 | 挙動 |
|---|---|---|
| 左右の親指を**交互に下へ払う** | 歩く | 下方向の動きだけが推進力になる。上へ戻す動きは足を前に運び直す動作にあたり、空振りする |
| 同じ親指を続けて払う | — | ゲインが `sameFootGain`（既定 0.22）まで落ちる。左右交互でないと前へ進まない |
| **両親指を結ぶ線**を傾ける | 回る | この線＝肩のライン。線が回った角度がそのまま進行方向に乗る（既定 1:1） |
| 片方を置いたまま、もう片方を弧に動かす | その場で回頭 | 上の特別な場合。9時→10時の30度で30度回る |
| 親指を離して置き直す | 持ち替え | 基準を取り直すので回頭しない。ハンドルを持ち替えるように何度でも回り続けられる |

前進は指の動きと **1:1 で即時**に反映する（平滑化すると足の裏の感じが鈍る）。

### 蛇行（まっすぐ歩けないこと）

目を閉じて歩くと、人間は実際にまっすぐ歩けない。少しずつ逸れて、やがて円を描く。
これを難易度調整ではなく**モデルとしてそのまま**入れてある。

一歩ごとに、持続性のあるランダムウォーク（AR(1)、既定の持続性 0.88）で進行方向が逸れる。
毎歩バラバラに揺らすと単なるノイズになって方向感が消えるので、
**しばらく同じ方向へ曲がり続ける**性質を持たせている。

結果として「音のほうを向いて、あとは真っ直ぐ」が成立しなくなり、
数歩ごとに聴き直して直す必要が生まれる。歩き続けている間ずっと耳を澄ませている状態になる。

## 音の設計

| 音 | 定位 | 役割 |
|---|---|---|
| **足音** | させない（左右のパンのみ） | 自分の足元で鳴るもの。左右で質感を変え、どちらの足で踏んだかが分かる |
| **landmark** | バイノーラル（HRTF） | 遠くで鳴り続ける方角の基準。これが無いと自分がどれだけ回ったのか読めない |

`AVAudioEnvironmentNode` の HRTF レンダリングで空間化している。
自分が30度回れば音源は逆に30度回るので、**耳だけで自分の向きが読める**。

音源が1つだけだと「動いた」しか分からないが、複数あると星座が回るように角度が読める。
そのため探索対象とは別に、方角の基準になる landmark を必ず置く設計にしている。

> **HRTF には正面と真後ろを取り違えるという人間側の限界がある。**
> これを解消する唯一の方法が首や体を振ることなので、
> 回頭は移動手段であると同時に「曖昧さを解く行為」でもある。

## 触覚の設計

一歩ごとの短いトランジェント。左右でわずかに質感を変えてあり、
どちらの足で踏んだかが触覚だけでも分かる。

連続触覚のしくみ（無限ループパターン＋Dynamic Parameters）は
`HapticsController` にそのまま温存してある。距離に連動する持続音を重ねる余地を残すため。

## 操作

| 操作 | 動作 |
|---|---|
| 両親指を交互に下へ払う | 歩く |
| 両親指を結ぶ線を傾ける | 曲がる |
| 3本指タップ | デバッグ表示のトグル |
| 2本指ダブルタップ | タイトルへ戻る |
| タイトルの「VOID」を長押し（1.2秒） | デバッグ表示のトグル（隠しスイッチ） |
| タイトルの「触覚テスト」 | 実機で触覚が動くかの確認（弱くざらつく → 強くなめらか → パルス） |

デバッグ表示では、歩数・現在地・進行方向・速度・蛇行量・足ごとの踏み込み量・
landmark の方位と距離がリアルタイムで見える。

## 動かし方

```
open haptic-void/HapticVoid.xcodeproj
```

1. TARGETS → HapticVoid → Signing & Capabilities で自分の Team を選ぶ
   （`PRODUCT_BUNDLE_IDENTIFIER` は必要に応じて変更）
2. **実機（iPhone）** を選んで Run
3. **ヘッドホンを着ける**（スピーカーだと空間定位は完全に失われる）

> `.xcodeproj` は `project.yml` から XcodeGen で生成している。
> ファイルを追加・削除したら `cd haptic-void && xcodegen generate` で作り直す。
> 署名設定（`DEVELOPMENT_TEAM` / `PRODUCT_BUNDLE_IDENTIFIER`）も `project.yml` 側に
> 入れてあるので、再生成しても崩れない。

- iOS 17.0+ / Swift 5 / 依存ライブラリなし
- ポートレート固定・フルスクリーン

## シミュレータでの挙動（重要）

**Core Haptics はシミュレータでは動作しない。** 実機テストが前提。

- `CHHapticEngine.capabilitiesForHardware().supportsHaptics` を起動時に確認し、
  false ならハプティクス層は**すべて no-op になる**（クラッシュも例外も出ない）
- 音とデバッグ表示はシミュレータでも動くので、**歩行ロジックの検証はできる**
  （歩数・現在地・進行方向・landmark の方位が数値で追える）
- タイトル画面に「⚠︎ この端末では触覚が再生されません（音のみで動作します）」と表示される

つまり **シミュレータ = 「数値でロジックを見る」用、実機 = 「歩き心地を詰める」用**。

なお実機でも、以下の場合は振動しない:
- 低電力モードがオン
- アプリがフォアグラウンドにない（**画面オフ中は触覚も音も止まる。iOSの制約**）
- iPhone 7 以前 / iPad（Taptic Engine 非搭載）

コンセプトの「画面オフでも成立する」は iOS では実現できないため、代わりに
真っ黒な画面＋`isIdleTimerDisabled = true`（自動ロックを止める）で、
目を閉じたまま中断されない状態を作っている。

## パラメータ調整

数値はすべて `HapticVoid/Core/Tuning.swift` に集約してある。ロジックには一切ハードコードしていない。

```swift
Tuning.Walk.strideStrokeRatio        = 0.11  // 一歩ぶんの親指ストローク（画面高さ比）
Tuning.Walk.strideAdvance            = 0.7   // 一歩で進む距離（メートル）
Tuning.Walk.sameFootGain             = 0.22  // 同じ足を続けたときのゲイン。1.0 で歩行感が消える
Tuning.Walk.steeringGain             = 1.0   // 肩のライン → 進行方向。1.0 で 1:1
Tuning.Walk.invertSteering           = false // 曲がる向きが逆に感じたらここ
Tuning.Walk.blindDriftDegreesPerStep = 2.2   // 蛇行の大きさ。0 で完全にまっすぐ歩ける
Tuning.Walk.blindDriftPersistence    = 0.88  // 大きいほど同じ方向へ逸れ続ける
Tuning.Footstep.clickFrequency       = 220   // 低く短いほど「コツッ」、高く長いほど「カツン」
Tuning.Audio.enabled                 = true  // 触覚だけの体験を試すときは false
```

### おすすめの詰め方

1. まず `blindDriftDegreesPerStep = 0` にして、**歩幅と足音のリズム**だけを詰める
   （`strideStrokeRatio` と `strideAdvance`）
2. `steeringGain` で曲がりやすさを取る。交互に払うと肩のラインが左右に振れるので、
   歩いているだけでも自然に揺らぐ。この揺らぎが強すぎるならここを下げる
3. `sameFootGain` で「片手だけでは進めない」の強さを決める
4. 最後に蛇行を戻し、数歩ごとに聴き直す頻度がちょうどよくなる量を探す

### 実装メモ

- **`DragGesture` は指を1本しか区別できない**ので、両手の親指を別々の足として扱うには
  UIKit のマルチタッチ層（`DualThumbTracker`）が要る。`UITouch` のインスタンスを
  そのまま識別子に使い、どちらの指が動いたのかをフレームをまたいで追跡している。
- 回頭は肩のラインの**角度の差分**を積むので、指を置き直しても回頭しない。
  1フレームで飛びすぎた変化（既定 25度超）は持ち替えとみなして捨てている。
- 連続触覚は**1本の無限ループパターンを鳴らしっぱなし**にして、Dynamic Parameters
  （`hapticIntensityControl` / `hapticSharpnessControl`）だけを書き換える設計を温存。
  毎回パターンを作り直すと途切れてグラデーションにならないため。
- `hapticSharpnessControl` は絶対値ではなく**イベント鋭さへの加算オフセット**（-1...1）。
  パターン側の基準値を 0.5 に置き、`目標値 - 0.5` を送ることで絶対値指定に見せている。
- 指が静止するとタッチイベントが止まるので、更新は CADisplayLink の固定ティックで回している。
- 空間音源は**モノラルで繋がないと定位が効かない**。`AVAudioEnvironmentNode` への接続は
  モノラル、出力はステレオ。landmark はループの継ぎ目が出ないよう、
  バッファ長にちょうど整数周期ぶん収まる周波数へ丸めて生成している。
